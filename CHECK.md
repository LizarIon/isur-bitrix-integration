# Проверка работы интеграции

Документ для тестировщиков и администраторов.

> **Перед проверкой** убедитесь, что интеграция установлена и настроена согласно `README.md`.

---

## ▶️ Что происходит при запуске

Программа:

- Проверяет наличие новых проектов в ИСУР и создает для них группы в Битриксе
- Запускает таймер (прямая синхронизация каждые 30 минут)
- Запускает веб-сервер для приёма вебхуков (порт 5000)

---

## 🧪 Сценарии проверки

### 1. Проверить логи

Логи пишутся в `logs/sync.log` с ротацией (10 МБ × 5 файлов).

Чтение:

```bash
tail -f logs/sync.log                                # Linux / macOS
Get-Content logs\sync.log -Tail 30 -Encoding UTF8    # Windows PowerShell
```

Убедитесь, что синхронизация запускается: в логе появятся строки о проходах 1–3 и итоговое `✅ ПРЯМАЯ СИНХРОНИЗАЦИЯ ЗАВЕРШЕНА`.

### 2. Проверить эндпоинты

Веб-сервер работает на порту **5000**.

| Метод | Путь | Что проверяет |
|---|---|---|
| `GET` | `/health` | Сервис жив |
| `GET` | `/status` | Последняя синхронизация, число связок, расхождений |
| `POST` | `/webhook` | Приём вебхуков от Битрикс24 |

Ожидаемо: `/health` и `/status` возвращают JSON, `/webhook` с пустым телом — `{"error":"Invalid request"}`.

### 3. Проверить вебхуки

1. Завершите задачу в Битрикс24
2. Проверьте логи — должно появиться сообщение о полученном вебхуке
3. Проверьте, что задача закрылась в ИСУР

### 4. Проверить резервную сверку

Резервная сверка запускается раз в сутки в указанное время (из `.env`). В логах появится:

```
🔄 ЗАПУСК РЕЗЕРВНОЙ СВЕРКИ
✅ Закрыта задача ... (сверка)
```

### 5. Проверить мультипроектность и пересчет

- Создайте новый проект в ИСУР. Перезапустите код. В логах должно появиться `Создана группа Битрикс 'Название'`, и в Битриксе появится новая группа.
- В Битриксе измените дату у задачи-предшественника. В ИСУР должна сдвинуться не только следующая за ней задача, но и все зависимые от нее (каскадный пересчет).

## ❗ Возможные проблемы и ошибки

| Проблема | Решение |
|---|---|
| `ModuleNotFoundError` | Проверьте, что установлены все зависимости (`pip install -r requirements.txt`) |
| `Invalid URL 'None'` | Проверьте `.env` — все переменные должны быть заполнены |
| Вебхук не приходит | Проверьте URL в настройках Битрикс24, доступность сервера (туннель ngrok) |
| База данных заблокирована | Закройте другие программы, работающие с `sync.db` |
| Кракозябры в логах Windows | Используйте `Get-Content logs\sync.log -Encoding UTF8` |
| Задача «выпадает» из папки | Проверьте, что при PUT передается `Parent_Id` (структура `update_isur_task`) |
